# 과학 문서 작성 형식

## 제목과 읽기 순서

- 문서 맨 위의 YAML front matter에는 범위와 목적을 담은 한국어 한 문장 `description`을 쓴다. 추가 필드는 실제 사용처가 있을 때 도입한다.
- H1 하나를 문서의 정식 제목으로 삼는다. `# MOSFET: Basic operation`처럼 번호 없는 영문 sentence case로 쓰고 약어·고유명의 대소문자를 지킨다.
- 절 제목은 `## 1. 표면 반응의 포화`, `### (1) 전구체 주입` 형식으로 쓴다. H3까지 사용한다. 한국어 명사구를 기본으로 하고 현상이나 방법의 고유명은 살린다. 절의 결론과 세부 조건은 첫 문단에서 설명한다.
- 새 글이나 전면 개정은 [목차 설계](../.agents/skills/outline-wiki-article/SKILL.md)에서 시작한다. 선행 개념은 처음 필요한 곳에서 실제 문서에 상대 경로로 연결하고, 개념명이나 문서명을 링크 문구로 쓴다.
- 각 절은 독자가 파악해야 할 관계부터 제시하고 유도·사례·예외로 이어 간다. 한 문단에는 한 논지를 담는다. 정의는 한 곳에서 설명하고 뒤에서는 새로 필요한 조건만 보탠다. 요약은 정의·핵심 관계·가정·한계를 3–6개 항목으로 정리한다.

## 한국어 문장과 용어

[용어 색인](terminology.md)은 본문·소제목·표·그림 설명이 함께 사용한다. 본문은 ‘~이다’, ‘~한다’로 쓴다. 표의 일반 열 이름과 설명도 한국어로 쓴다.

1. 문장을 소리 내 읽듯 따라가며 **무엇이, 어떤 조건에서, 무엇을 어떻게 바꾸는지** 확인한다. 대상이 바뀌거나 비교 기준이 모호해지면 명사를 다시 적는다. 주체가 명백하면 자연스러운 생략을 살린다.
2. 명사가 겹치면 관계를 동사로 풀어 쓴다. ‘주입 시간 증가에 따른 성장량 변화의 확인’은 ‘주입 시간을 늘리면서 사이클당 성장량이 어떻게 변하는지 확인한다’로 쓸 수 있다. ‘~에서의’, ‘~에 대한’, 피동·진행 표현은 문맥에서 조건·대상·상태가 명확할 때 그대로 쓴다.
3. 문장을 나눈 뒤에도 조건·부정·비교·수식어가 같은 주장에 걸리는지 확인한다. ‘항상 성립하지는 않는다’와 ‘성립하지 않는다’는 다르다. 앞뒤 문장에 인과·대조 관계가 드러나면 연결어로 밝혀 준다. 행위자, 인과관계, 시제, 필요·충분조건을 추측해 넣지 않는다.
4. 수정한 뒤에는 손대지 않은 문장까지 포함해 요청 범위의 문단을 다시 읽는다. 지시어가 가리키는 대상과 문장 사이의 연결을 복원할 수 있는지 확인한다. 과장된 평가나 내용 없는 도입은 덜어낸다. 어려운 관계는 실제 소자·물질·계산 단계의 예로 설명한다. 예제에도 같은 가정·기호·인용 기준을 적용한다. 생략된 대상을 복원하는 예는 [문장 재구성 사례](../.agents/skills/polish-wiki-korean/references/sentence-revision-examples.md)를 참고한다.

## 정의·수식·코드

- 핵심 용어와 물리량은 첫 사용 때 정의한다. 식 전후에서 기호·단위·각 항의 의미를 설명하고, 정확한 관계인지 근사인지, 어떤 조건과 범위에서 쓰는지 밝힌다. 유도를 줄이면 생략한 단계를 밝힌다. 기호만 다시 나오는 문장에는 필요에 따라 물리량 이름을 보탠다.
- 한 문서에서 같은 기호의 뜻, 부호, 좌표축, 지수 및 정규화 기준을 일관되게 쓴다. 전류의 부호와 크기, 면적·폭·길이당 값을 구분한다. 문헌 간 규약이 다르면 변환을 보인 뒤 비교한다. 추론에는 전제와 근거를 밝힌다.
- 인라인 수식은 `$...$`, 독립 수식은 별도 줄의 `$$` 사이에 적는다. 코드 블록에는 언어를 표시하고 필요한 입력값·실행 조건은 앞에서 설명한다.

## 그림·표·측정

- 새 과학 문서와 요약 도식을 요청받은 기존 글에는 [도입용 요약 도식](../.agents/skills/illustrate-wiki-summary/SKILL.md)을 준비한다. 생성형 이미지는 본문에서 근거를 확인한 개념을 요약하는 이 도식에만 사용한다. 측정 곡선·현미경 사진·시뮬레이션 결과는 원자료에서 가져온다.
- 도입 도식은 문서마다 한 장을 **요약 그림**으로 구분한다. `<figure id="summary-figure" markdown="span">`에 넣고 캡션을 번호 없이 `요약 그림. …`으로 시작한다. 본문에서 이 도식을 가리킬 때는 `[요약 그림](#summary-figure)`으로 연결한다. 본문 그림 번호는 요약 그림을 제외하고 `그림 1`부터 센다.
- 공간 구조·경로나 순서는 출처 있는 그림, 같은 조건에서 방법이나 결과를 비교할 때는 표, 정량 관계는 수식을 우선한다. 도입 문단 뒤에 그림에서 볼 지점을 짚고 결과를 해석한다. 여러 절이 같은 그림을 쓰면 처음 나온 곳으로 연결한다. 표 앞에 비교 대상과 기준을 밝히고 작은 화면에서도 읽히는지 확인한다.
- 소자 구조 그림에는 관련 단자·전류 경로·전기장 방향을, 측정 그림에는 바이어스 연결이나 지표를 읽을 구간을 확인한다. 문헌 그림의 확보·허가·출처 표기는 [그림 스킬](../.agents/skills/acquire-scientific-images/SKILL.md)을 따른다. 그림은 `<figure markdown="span">`, 캡션은 `<figcaption markdown="1">`에 넣고 캡션 안 수식에도 `$...$`를 쓴다.
- 측정으로 설명하는 현상은 각 현상 뒤에 아래 블록을 둔다. 독자가 곡선에서 직접 지표를 구할 수 있도록 실제 추출식, 단위, 구간까지 함께 적는다.

```markdown
!!! info "[Measurement]"
    단자 연결, 고정 조건, 주사 변수와 필요한 소자군을 적는다.
    측정 곡선의 어느 구간에서 어떤 값으로 지표를 계산하는지 설명한다.
```

- 온도·바이어스·정규화·회귀 구간·통계량이 길면 `!!! abstract "[Metric]"`에 보충한다. 해석상 혼동 요인은 `!!! warning "[Interpretation Caveat]"`로 구분할 수 있다. 그 밖의 알림 블록도 가정·한계·예제가 본문과 구분될 때 쓴다.

## 인용

주장을 뒷받침하는 문장 바로 뒤에 `[1,2]`처럼 번호를 붙인다. 번호를 매긴 마지막 참고문헌 절에 본문 등장 순서대로 저자, 원제, 학술지·권·쪽·연도, DOI 또는 안정적인 URL을 쓴다. 책은 판·출판사를, 소프트웨어 문서는 버전을 식별한다. 출처 판단과 원문 확인은 [조사 원칙](research-workflow.md)을 따른다.
