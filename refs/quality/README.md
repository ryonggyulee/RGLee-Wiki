# 사실 검증과 게시 검사

작성자는 [글쓰기 안내](../writing.md)에 따라 문장을 다듬는다. 독자 관점의 편집 검토는 사용자가 요청할 때만 진행한다.

게시하려면 해당하는 항목을 모두 통과해야 한다.

- [ ] 문서 형식, 메뉴, 내부 링크와 인용 번호가 유효하다.
- [ ] 과학 문서는 사실·출처 검토를 통과했고, 그 기록은 현재 내용과 일치한다.
- [ ] MkDocs 엄격 모드 빌드에 성공했다.

검사 결과에서 `[x]`는 통과, `[ ]`는 미통과, `[-]`는 대상이 없거나 실행하지 않은 항목을 뜻한다.

## 작업별 검증 경로

| 변경 | 기록과 최종 검사 |
| --- | --- |
| 메뉴 라벨·순서만 변경 | `./build.sh nav` |
| 의미를 보존한 제목·설명·경로·목차·윤문 | diff를 읽고 `./quality.sh sync --non-scientific <경로...>` 후 범위 빌드. `--polish`도 같은 동작 |
| 과학적 주장·수식·수치·그림의 의미·인용 변경 | 아래의 범위 결정 → 독립 검토 → 등록 → 범위 빌드 |
| Home·색인 변경 | 완료한 경로를 sync한 뒤 범위 빌드 |
| 상태 조회·감사·지침만 변경 | 읽기 전용으로 확인한다. 지침을 고치면 바뀐 안내와 링크를 확인한다 |
| 검사 도구 변경 | 관련 회귀 테스트와 `./build.sh build`를 실행한다 |

범위 빌드에서는 `./build.sh changed`와 `git diff --check`를 실행한다. 메뉴와 본문을 함께 바꾸면 본문 기준을 따른다. 전체 게시 검사는 `./build.sh build`, diff와 변경 파일 목록까지 확인할 때는 `./build.sh preflight`를 쓴다.

## 기준 버전과 변경 범위

기존 문서는 먼저 `./quality.sh baseline <문서>`로 마지막 검증본과 비교한다. 최근 커밋이나 작업 트리의 diff만 보면 이미 커밋한 미검증 변경을 놓칠 수 있다. `coverage.mode: changes`는 그 뒤 달라진 주장, 선행 가정과 종속 결론을 포함한다. 이전 근거의 경로·파일 SHA·그대로 적용되는 범위를 명시한다. 새 글과 검증본을 복구할 수 없는 글은 `full`로 전체 주장을 확인한다.

제목·description·캡션에도 과학적 주장이 있을 수 있다. 의미 보존 여부는 실제 변경으로 판단한다. 미완료·실패 기록과 내용이 바뀐 추적 이미지는 이전 pass를 승계할 수 없다. Markdown 이미지 파일의 hash는 추적하지만 HTML·외부·간접 참조, 과거 기록에 없는 이미지는 수동으로 영향을 확인한다.

## 과학 문서 한 건의 검토와 등록

1. 작성자는 편집을 마치고 diff를 확인한 뒤 `./quality.sh sync <완료한 경로...>`를 한 번 실행한다. 이동은 이전·새 경로 모두, 삭제는 이전 경로를 지정한다. 전체 sync는 전체 갱신이 목적일 때만 사용한다.
2. 작성에 참여하지 않은 검토자 한 명이 `audit-wiki-references`로 주장과 인용을 원문과 대조한다. 다른 사람이나 작성 대화를 상속하지 않은 별도 세션·기본 에이전트가 맡을 수 있다. 전용 프로필은 필요 없다. 입력은 저장소와 최종 파일 경로·SHA-256, 마지막 검증본, 검토 범위와 `experiment/<작업>/<문서>/facts.yaml` 출력 경로이다. 작성자의 자체 판정 없이 시작하고, 첫 판단 후 이전 근거의 재사용 범위를 확인한다. 추가 검토자는 출처 충돌이 남거나 요청받았을 때만 둔다.
3. 검토자는 [조사 원칙](../research-workflow.md)에 따라 원문 위치, 출처의 독립성, 조건, 대조·검산 결과, 미확인 사유를 [사실 검토 양식](assessment-template.yaml)에 적는다. [판정 규칙](rubric.yaml)은 항목별 상태와 필요한 출처 수를 정한다. 모델 정보는 확인한 값만 쓴다. 독립 검토자가 없으면 미검증 상태로 둔다.
4. 등록 담당자가 현재 본문·로컬 그림의 SHA와 결과 파일을 대조하고 문서별로 순차 등록한다. 명령은 `./quality.sh review <문서> --assessment <facts.yaml>`이다. 근거는 내용 hash로 식별하여 보존한다. 검토 후 수정하면 새 SHA에서 바뀐 항목과 의존 항목을 다시 확인한다.
5. `mismatch`가 있으면 `revise`, 근거 부족(`insufficient`)이나 접근 실패(`inaccessible`)가 남으면 `unverified`, 모두 `supported`이면 `pass`이다. 렌더링만 실패했다면 근거 검토를 반복하지 않는다.

## 읽기 전용 명령과 기존 기록

- `./quality.sh report --changed` 또는 `report <경로...>`는 저장 상태를 보여 준다. `check --all`, `check --changed`, `check <경로...>`는 현재 파일과 형식·인용 번호·링크·hash·근거 참조를 검사한다. `check-nav`는 탐색 구조를 검사한다.
- `benchmark <경로>`는 참고용으로 글자 수와 그림·표·수식·코드 블록 수의 합을 보여 준다.
- 과거 점수는 이력으로 보존한다. 현재 문서에 유효한 이전 제도의 통과 기록(`legacy`)은 검사 결과에 건수를 표시한다. 다음 과학적 변경부터는 달라진 주장과 그 영향을 원문과 대조한다.
