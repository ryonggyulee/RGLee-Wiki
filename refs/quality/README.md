# 사실 검증과 게시 검사

`documents.yaml`에는 현재 메타데이터와 검증 근거의 참조를 저장한다. Git에는 이력을 남긴다. [평가 양식](assessment-template.yaml)이 필드 정의의 기준이며, [판정 규칙](rubric.yaml)이 상태·범주별 최소 출처 수를 정한다.

## 작업별 검증 경로

| 변경 | 기록과 최종 검사 |
| --- | --- |
| 메뉴 라벨·순서만 변경 | `./build.sh nav` |
| 의미를 보존한 제목·설명·경로·목차·윤문 | diff를 읽고 `./quality.sh sync --non-scientific <경로...>` 후 범위 빌드. `--polish`도 같은 동작 |
| 과학적 주장·수식·수치·그림의 의미·인용 변경 | 아래의 범위 결정 → 독립 검토 → 등록 → 범위 빌드 |
| Home·색인 변경 | 완료한 경로를 sync한 뒤 범위 빌드. 사실 검토 대상은 과학 문서 |
| 상태 조회·감사·지침 또는 도구만 변경 | 문서 기록은 쓰지 않는다. 도구·지침 개정 시 관련 회귀 테스트와 `./build.sh build`로 전체 게시 조건 확인 |

범위 빌드는 `./build.sh changed`와 `git diff --check`이다. 메뉴와 본문을 함께 바꾸면 본문 경로의 검사를 적용한다. 전체 위키 게시 검사는 `./build.sh build`, 여기에 diff와 대상 파일 목록까지 확인하려면 `./build.sh preflight`를 사용한다. 빌드는 strict MkDocs와 자동 검사를 포함한다.

## 기준 버전과 변경 범위

기존 문서는 먼저 `./quality.sh baseline <문서>`로 마지막 검증본과 비교한다. 최근 커밋이나 작업 트리의 diff만 보면 이미 커밋한 미검증 변경을 놓칠 수 있다. `coverage.mode: changes`는 그 뒤 달라진 주장, 선행 가정과 종속 결론을 포함한다. 이전 근거의 경로·파일 SHA·그대로 적용되는 범위를 명시한다. 새 글과 검증본을 복구할 수 없는 글은 `full`로 전체 주장을 확인한다.

제목·description·캡션에도 과학적 주장이 있을 수 있다. 의미 보존 여부는 실제 변경으로 판단한다. 미완료·실패 기록과 내용이 바뀐 추적 이미지는 이전 pass를 승계할 수 없다. Markdown 이미지 파일의 hash는 추적하지만 HTML·외부·간접 참조, 과거 기록에 없는 이미지는 수동으로 영향을 확인한다.

## 과학 문서 한 건의 검토와 등록

1. 작성자는 편집을 마치고 diff를 확인한 뒤 `./quality.sh sync <완료한 경로...>`를 한 번 실행한다. 이동은 이전·새 경로 모두, 삭제는 이전 경로를 지정한다. 전체 sync는 전체 갱신이 목적일 때만 사용한다.
2. 작성에 참여하지 않은 검토자 한 명이 `audit-wiki-references`로 원문을 대조한다. 다른 사람이나 작성 대화를 상속하지 않은 별도 세션·기본 에이전트가 맡을 수 있다. 전용 프로필은 필요 없다. 입력은 저장소와 최종 파일 경로·SHA-256, 마지막 검증본, 검토 범위와 `experiment/<작업>/<문서>/facts.yaml` 출력 경로이다. 작성자의 자체 판정 없이 시작하고, 첫 판단 후 이전 근거의 재사용 범위를 확인한다. 추가 검토자는 출처 충돌이 남거나 요청받았을 때만 둔다.
3. 검토자는 자기 문서의 사실 기록만 작성한다. 원문 위치, 독립성, 조건·규약, 직접 대조 또는 재현 가능한 검산, 미확인 사유를 [조사 원칙](../research-workflow.md)에 맞춰 적는다. 모델 정보는 확인한 값만 쓴다. 검토자가 없으면 미검증 상태를 알리고, 작성자의 재독을 독립 검토로 등록하지 않는다.
4. 등록 담당자가 현재 본문·로컬 그림의 SHA와 결과 파일을 대조하고 문서별로 순차 등록한다. 명령은 `./quality.sh review <문서> --assessment <facts.yaml>`이다. 근거는 내용 hash로 식별하여 보존한다. 검토 후 수정하면 새 SHA에서 바뀐 항목과 의존 항목을 다시 확인한다.
5. `mismatch`가 있으면 `revise`, 근거 부족(`insufficient`)이나 접근 실패(`inaccessible`)가 남으면 `unverified`, 모두 `supported`이면 `pass`이다. 현재 버전의 pass와 자동 검사·strict 빌드를 모두 확인한 뒤 게시한다. 렌더링만 실패했다면 근거 검토를 반복하지 않는다.

## 읽기 전용 명령과 기존 기록

- `./quality.sh report --changed` 또는 `report <경로...>`는 저장 상태를 보여 준다. `check --all`, `check --changed`, `check <경로...>`는 현재 파일과 형식·인용 번호·링크·hash·근거 참조를 검사한다. `check-nav`는 탐색 구조를 검사한다.
- `benchmark <경로>`는 분량과 설명 요소를 집계한다. 게시 기준에 편집 점수, 최소 분량, 그림 개수는 없다. 자동 검사는 구조·신선도·선언된 출처 수를 검사한다. 주장의 누락과 실제 근거의 타당성은 사실 검토자가 확인한다.
- 현재 파일과 일치하는 기존 rubric v3 pass는 `legacy`로 유지한다. 그 기록을 새 검토로 바꾸지 않는다. 다음 과학적 변경부터 v4 범위와 근거를 남기며, 이전 근거의 가정이 달라졌으면 해당 부분을 직접 확인한다.
